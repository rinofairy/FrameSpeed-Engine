## 1. 启动与使用

运行 [FrameSpeedSerial.exe](../05_SerialTool/FrameSpeedSerial.exe)，选择实际串口，波特率 115200。本机记录为 COM6，其他电脑不保证同号。连接后菜单显示两个框，1/E 进入 Demo，2/G 进入游戏；M 从应用返回菜单。菜单也支持 W/S 选择、回车确认。

进入 Demo 后，先选 `1` 检查纯色填充，选 `2` 检查双色图搬运，选 `3` 进入精灵压力测试。FPGA 与 CPU 渲染切换使用 H/C，画面上显示 FPS、元素量和模式。菜单/Flash 启动流程见 [引擎开发说明](../01_Engine/README.md)。

如果只是运行已部署的固件，打开串口工具即可；不要运行写 Flash 命令来切换场景。同一串口只由一个工具占用。

## 2. Demo 的逻辑、操作与公平对比

### 2.1 三类展示

| 入口 | 工作内容 | 主要验证目的 |
|---|---|---|
| `1` | 纯色矩形填充 | 实际使用硬件 Solid Fill，展示 CPU 对照 |
| `2` | 32×32 双色图像搬运 | 展示图像块搬运；可切键控和 Alpha |
| `3` | 大量动态图集精灵 | 使用批量扫描线路径，展示吞吐率和优化开关 |

双色图案是已经在内存中的图像，运行时通过搬运绘制，不是 CPU 每帧重画素材。顶栏显示 FPS、元素量、CPU/FPGA 模式，其他诊断信息从串口输出。

Demo 的对象位置更新由 CPU 执行，渲染模式切换只改变如何生成相同画面的像素。批量模式初始化图集和背景，再准备当前 bank；硬件执行当前帧期间按设置生成下一帧 bank；完成后更新信息栏并按显示流程换帧。

### 2.2 Demo 控制

按键名称按串口工具按钮/键盘理解，普通终端发送对应小写字符；`+/-`、`[]` 等符号保持原样。

| 键 | 功能 |
|---|---|
| `1 / 2 / 3` | 填充 / 32×32 双色搬运 / 批量精灵 |
| `4 / 5 / 6` | 晶体 / 圆球 / 混合材质 |
| `+ / -` | 元素量增减 32，范围受应用上限 2048 约束 |
| `H / C` | FPGA / CPU 绘制 |
| `A` | 切 Alpha 开关 |
| `K` | 切颜色键开关 |
| `[ / ]` | Alpha 以 16 为步长减/增，夹到 0～255 |
| `B` | 轮换黑色、原尺寸背景、缓存暗背景；缺原尺寸素材时跳过相应项 |
| `O / T / V` | 普通 / 透明包围框 / 逐行透明区间 |
| `P / D` | APB 上传命令 / 命令表 DMA |
| `R / S` | CPU 准备和 FPGA 绘制重叠 / 串行 |
| `J / U` | FPGA 双行合成写回重叠 / 串行调度 |
| `F` | 冻结测试画面，用于正确性检查 |
| `M` | 返回菜单，需要整套启动器已初始化 |

默认批量精灵 640 个，Alpha=192，颜色键与 Alpha 开启，APB 命令上传，CPU 重叠和双行重叠开启。2048 是 Demo 软件对象容量，**不是保证 2048 个任意尺寸、任意效果都达 60 FPS**。

### 2.3 公平性能对照

CPU 和 FPGA 对照应使用相同素材、位置序列、尺寸、可见范围、颜色键、Alpha、背景及换帧规则。CPU 参照路径用同样的 RGB565 取整，而不是用更低精度混合；硬件路径不允许减少对象后仍保留相同“数量”标签。

建议每组记录：模式、尺寸/材质、请求对象量、裁剪后描述符量、效果、背景、优化开关、新帧 FPS、CPU 准备时间、硬件周期、工作最大耗时、字节计数、欠载/AXI 错误。改变尺寸或背景后应重新测，不能仅比较屏幕上一个 FPS 数字。

如果两模式都达到显示上限 60，`60/60=1` 不能说明没有加速；这时比较完成绘制的耗时、最大可承受负载和 CPU 可用时间。若一种未达到 60，可报告相同条件下实际 FPS 比值，但要同时标明刷新上限和测试场景。

## 3. 源码、画面和内存布局

Demo 工程位于 [07_Demo](../07_Demo)，工程名 `FrameSpeed_Release_Demo`，与游戏分别编译，共用 `01_Engine` 驱动和同一 FPGA 位流。

| 文件 | 职责 |
|---|---|
| [demo_main.c](../07_Demo/src/demo_main.c) | 启动自检、串口控制、双命令 bank 调度、换帧和性能日志 |
| [demo_control.c](../07_Demo/src/demo_control.c) | 场景/模式/数量/透明度的控制状态 |
| [suite_demo.c](../07_Demo/src/suite_demo.c) | 运动对象准备、填充与双色图的 CPU/硬件绘制 |
| [taisei_render.c](../07_Demo/src/taisei_render.c) | 纹理选择、裁剪/分区、描述符构建、逐行硬件合成和 CPU 对照 |
| [sh_assets.c](../07_Demo/src/sh_assets.c)、[sh_background.c](../07_Demo/src/sh_background.c) | Demo 图集、透明元数据和背景路径 |

HDMI 为 640×480：顶部 48 行是信息区，下部 640×432 为绘图区。绘图区分成 8 个高 54 行的区域，依次提交同一合成器。一个跨区域精灵可生成多个描述符，区域数量不是引擎并行数量，也不是 AXI 突发数量。

命令 bank A 被 FPGA 使用时，CPU 在 bank B 准备下一帧。当前帧素材、描述符和设置快照保持不变；整帧及顶栏完成后才交换帧缓冲。双行重叠则发生于 FPGA 内，合成下一行与写回上一行并行；两项优化可独立切换。

| 用途 | 地址/布局 |
|---|---|
| 图集源数据 | `0x00630000` |
| 原始游戏/素材包头 | 不适用 |
| 主背景像素 | `0x00740000`，头在 `0x0073FFC0` |
| 命令 bank 0 | `0x00720000` |
| 命令 bank 1 | `0x00710000` |
| 每 bank 大小 | `0x10000`，8×8192 字节 |
| 辅助材质/背景 | 纹理 `0x00600000` 一带，暗背景 `0x00680000` |

完整帧缓冲为 `0x800000/0x900000`，每帧 614400 字节，跨度 1280 字节；HUD 暂存在 `0xA00000`。软件对象容量为 2048，单区域硬件描述符上限为 512，持续 60FPS 的容量须按下面实测条件理解。

Demo 的原尺寸背景为 640×432，背景包头位于 `0x73FFC0`、图像位于 `0x740000`，有效像素字节数 552960。载入时验证头字段和 CRC。背景和材质在 CPU 参考路径与 FPGA 路径中使用相同内容。

## 4. 性能、压力测试与验证

### 4.1 交付镜像功能场景

数据来自 [runtime.json](../06_Verification/flash_install/runtime.json) 和 串口日志（本地完整工程路径：`../06_Verification/flash_install/runtime_uart.log`）。

| 场景 | 条件 | 记录结果 |
|---|---|---|
| FPGA 填充 | Demo 纯色场景 | 最低统计窗口 60.0 FPS |
| CPU 填充 | 同类 Demo 场景 | 最低统计窗口 30.0 FPS |
| FPGA 通用双色搬运 | 32×32、64 项、无额外透明效果 | 最低统计窗口 29.5 FPS |
| FPGA 通用双色搬运 | 32×32、64 项、Alpha/颜色键 | 最低统计窗口 15.0 FPS |
| FPGA 批量精灵 | 默认 640 项、Alpha=192、键控、原尺寸背景、两级重叠 | 最低统计窗口 60.0 FPS |

### 4.2 24×24 元素压力测试

测试使用移动的 24×24 RGB565 圆球，HDMI 输出 640×480，顶部信息区 48 行，实际绘图区 640×432。开启 Alpha=192（约 75.3% 不透明度）、颜色键和静态原尺寸背景，使用普通矩形描述符、APB 命令上传；CPU 准备/FPGA 绘制重叠及双行合成/写回重叠均开启。包围框和逐行透明区间优化关闭，画面持续运动。

| 元素量 | 采集方式 | 最低窗口 FPS | 平均工作耗时 | 最大工作耗时 | 结果 |
|---:|---|---:|---:|---:|---|
| 1024 | 容量定位短测 | 60.0 | 12.292ms | 12.357ms | 达到 60FPS |
| 1280 | 容量定位短测 | 60.0 | 14.728ms | 15.307ms | 达到 60FPS |
| **1376** | **连续约 60.02 秒确认** | **60.0** | **16.016ms** | **16.084ms** | **持续 60FPS 的已确认点** |
| 1408 | 边界复测，约 30 秒 | 59.0 | 16.287ms | 16.497ms | 出现掉帧，未满足持续 60FPS |
| 1536 | 容量定位短测 | 30.0 | 17.918ms | 17.998ms | 超过单帧时间预算 |

容量边界按 32 个元素的精度定位。1376 个的确认记录包含 60 个统计样本；每个样本约一秒。所有列出的配置中，显示欠载和 AXI 错误均为零。1376 个在该测试配置下达到持续 60FPS；继续加元素仍能绘制，但不会保持相同帧率。

60Hz 换帧节奏下，一帧可用时间约 16.667ms。1536 个时工作耗时约 17.9ms，错过一次显示换帧边界，因而可能重复上一帧，实际新帧 FPS 降至约 30。1408 个靠近边界，即使测得的工作耗时略低于 16.667ms，采样/提交位置和剩余时序余量也会影响能否及时提交；因此容量以长测新帧计数为准，不只看单次耗时或短时 60FPS。

该结果是交付包随附的同一 `0x46534C06` 引擎及上述合成配置的专项 Demo 实测，采用独立 Demo 加载采集；统一 Flash 套件的入口回归记录见本章第一节。这里引用实际采集数据，没有将它描述为重新对当前 Flash 镜像测得的容量。原始数据见 [24×24 容量记录](../06_Verification/reference/demo/overlap_limit_20261018_182755/performance.json)，其 `boundaries` 给出确认数量、时长、步长和下一数量的结果。

复现时：从菜单进入 Demo，选 `3` 精灵、`5` 圆球，确认 Alpha=192、颜色键开启、B 选原尺寸背景，使用 `O/P/R/J` 分别选择普通矩形、APB、CPU 重叠和双行重叠。默认数量 640，按 `+` 23 次到 1376；再按一次到 1408。等待设置切换的预热窗口结束后再采集，记录 `fps10/objects/alpha/bg_mode/optimization/command_dma/overlap/line_overlap`。

### 4.3 性能日志

| 字段 | 含义/注意 |
|---|---|
| `fps10` | 实际完整新帧 FPS 的 10 倍 |
| `new_frames/scans/sample_us` | 新帧数、扫描次数、真实采样时间 |
| `work_max_us/work_avg_us` | 换帧等待前的工作耗时，不是单纯 FPGA 时间 |
| `logic_max_us/prepare_max_us` | CPU 逻辑和准备耗时，存在包含/重叠关系 |
| `core_cycles` | 硬件任务周期，按应用聚合；换算需使用对应核心频率 |
| `descriptors/descriptor_visits` | 实际描述符和逐行访问规模，不等于可见对象数 |
| `read_bytes/write_bytes` | 硬件数据流量，不是电脑串口字节 |
| `cmd_bytes/cmd_bursts` | 命令表 DMA 专属流量与突发数 |
| `skipped_pixels` | span 优化跳过的像素；不是所有颜色键透明像素总量 |
| `over_budget` | 工作时间超过约 16.667ms 的帧数 |
| `underrun/axi_errors` | 显示欠载/读取错误，不能只看 FPS 而忽略 |

降低统计频率能减少部分 CPU/串口开销，但不能把删除错误检查后“看起来正常”作为正确性证据。当前日志采用缓冲、非阻塞发送，不会每帧同步打印整屏数据。

### 4.4 正确性检查

Demo 启动时使用 CPU/FPGA 逐像素对照检查填充、搬运、颜色键、Alpha、APB/DMA、串行/双行及命令 bank 重叠，分别输出 `DEMO_PIXEL_MATCH` 与 `DEMO_OVERLAP_PIXEL_MATCH`。离线记录包含 561 组渲染对照和 15360 组裁剪检查。数量是测试规模，不是互不相关的功能数。

## 5. 构建与开发

在官方 RISC-V IDE 导入 [07_Demo](../07_Demo)，执行 Build Project。使用本工程 Makefile、`suite.ld` 和头文件配置，不将 `08_Game` 的同名 C/头文件一起加入编译。

```powershell
python tools/test_demo.py
```

离线测试验证像素/裁剪与命令生成，不能用其执行时间代替实板 FPS。修改后按 [引擎开发说明](../01_Engine/README.md) 的统一构建流程重建镜像；构建不会自动烧录。

只比较某个优化时保持元素尺寸、数量、纹理、背景、Alpha、颜色键、位置变化和换帧策略相同。先使用普通路径作为基准，每次只改 CPU 重叠、双行重叠、命令 DMA 或透明区间中的一项。

命令溢出时检查单区域描述符数、跨区域拆分和图案层数；单纯未超过 2048 个对象不代表每个区域都符合上限。M 返回菜单依赖 Suite 跳板和暂存已初始化。
