# FrameSpeed Engine / 帧速引擎

基于 RISC-V 与 FPGA 的 RGB565 二维图形加速系统，包含通用矩形填充与搬运、颜色键控、Alpha 混合、批量精灵逐行合成、HDMI 帧缓冲显示，以及 Demo 和 Taisei 关卡移植应用。

## 本仓库提供什么

这是**公开源码版**，用于阅读自定义加速器、驱动、调度、应用和性能记录。它与本机的完整 Flash 交付目录不同：本仓库**不包含厂商专有 FPGA IP、板级参考 RTL、BSP、完整 FPGA 工程或包含这些模块的预编译烧录镜像**。目前尚未确认上述文件的公开再分发许可，因此没有将它们提交。

本仓库不能在克隆后直接生成或烧录完整系统。复现需要自行从易灵思或板卡供应方取得、并按授权使用匹配的 Ti60F225 DemoBoard V4 参考工程、Sapphire SoC、DDR 控制器、显示接口及 BSP。文档中有关完整交付包的构建、烧录命令，适用于补齐这些本地依赖后的完整工程。

### 编译与烧录说明

本仓库源码对应 **Flash 启动的菜单＋Demo＋游戏版本**，不是此前独立下载到 RAM 的运行包。目标板为**易灵思 Ti60F225 DemoBoard V4，芯片 Ti60F225I3**。

取得匹配的易灵思参考工程、IP 和 BSP 后，还需将本项目接入板级顶层，完成总线、地址、时钟、复位、引脚及软件链接配置；不能仅把两套文件放在一起就直接编译。集成后使用 **Efinity** 编译 FPGA 配置、使用 **Efinity RISC-V IDE** 编译 CPU 程序，再与素材封装为完整 Flash 镜像，经时序检查和实板验证后烧录。本仓库不提供完整烧录镜像；已经取得匹配镜像的使用者无需重新编译全部源码即可烧录。

## 工作方式

RISC-V 执行应用逻辑与任务准备，APB 寄存器负责控制；自定义 FPGA 引擎经 AXI 直接访问 DDR。矩形引擎支持纯色填充和图像块拷贝，批量精灵路径按屏幕区域组织任务，并在片上逐行合成后写回 DDR 帧缓冲。显示模块独立读取前台缓冲，在换帧时切换。

优化包括 CPU 命令准备与 FPGA 绘制重叠、双行缓冲并行合成与写回、颜色键跳过及 RGB565 Alpha 运算。显示器刷新率与实际生成新画面的 FPS 分别统计，不能以重复扫描同一帧代替渲染性能。

## 性能记录如何阅读

在特定的 24×24 精灵、Alpha 192、颜色键开启、静态背景与匹配引擎配置下，1376 元素连续约 60 秒测试记录的新帧 FPS 最低为 60；1408 元素已出现最低 59 的样本。此结果只代表该场景，不能推广为任意素材、任意尺寸或游戏全关卡的容量保证。详细条件及原始记录见 [Demo 文档](07_Demo/README.md)。

这里的验证记录来自完整本地系统；不意味着公开版缺少厂商依赖时也能单独上板运行。修改代码后需要重新构建、仿真、检查时序并实测，旧记录不会自动证明新版本正确。

## 如何复现与继续开发

1. 先阅读三份工程说明，确定像素格式、时钟、地址布局和缓存所有权。
2. 自行获取匹配板卡的合法参考工程和 BSP；本项目使用的工具方向为 Efinity 与 Efinity RISC-V IDE。
3. 将 `01_Engine/fpga/rtl/fs_*.v` 集成到对应 SoC/DDR/显示工程，按说明接入 APB 控制与 AXI 存储访问；板级顶层、仲裁、复位和引脚配置需要与参考工程对应。
4. 将共享驱动、菜单、Demo 和游戏的 C 源码加入对应 IDE 工程，补齐 `.cproject` 中的 BSP、链接脚本和本机工具路径。
5. 从单个矩形、边界/跨度和像素正确性开始，再验证双缓冲、压力场景与性能；修改一项后再测下一项。
6. `tools/build_suite.py`、`board_flash.py` 等是完整交付版本的工具源码，依赖未公开的本地组件；请勿直接运行它们来写入不匹配的板卡。

公开文件完整性可执行：

```powershell
python tools/check_public.py
```

## 串口操作

已部署匹配固件的板卡，可运行 `05_SerialTool/FrameSpeedSerial.exe`，选择实际 COM 端口并使用 115200 波特率。菜单 1/E 进入 Demo，2/G 进入游戏，M 返回。Demo、游戏的完整按键表见各自说明。串口工具只发送输入和显示日志，不承担游戏逻辑或渲染。
