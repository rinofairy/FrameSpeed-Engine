## 1. 启动与操作

运行 [FrameSpeedSerial.exe](../05_SerialTool/FrameSpeedSerial.exe)，选择实际串口，波特率 115200。本机记录为 COM6，其他电脑不保证同号。连接后菜单显示两个框，1/E 进入 Demo，2/G 进入游戏；M 从应用返回菜单。菜单也支持 W/S 选择、回车确认。

| 按键 | 功能 |
|---|---|
| WASD | 移动 |
| 按住 J | 持续射击 |
| 按住 Shift | 半速移动 |
| R | 重开，保留当前会话 HI |
| I | 切换无敌，并标记测试使用 |
| P | 暂停/继续 |
| B | 滚动背景/黑色背景切换 |
| T | 无敌开启时进入道中 Boss 练习，保留 Power |
| N | 无敌开启时进入最终 Boss/跳下一阶段 |
| M | 返回菜单，需要完整启动器已初始化 |

游戏采用最高难度档，Power 从 1.00 起步，升级与拾取按本文规则进行。Demo 的 H/C/A/K 属于另一应用，不作为本游戏的渲染控制键。

## 2. 游戏主循环与命令生成

游戏是针对本板卡的 Taisei 第一关/琪露诺战改编。原作关卡计算被整理为固定步长 C 状态机、离线素材和本引擎命令，使用最高难度档。

### 2.2 启动顺序

1. 初始化 BSP，确认通用引擎、扫描线和显示三个 ID；
2. 检查素材包完整性，加载图集，启用双行重叠；
3. 构造一组包含越界裁剪、图层、拖尾、Alpha、键控和背景滚动的测试命令；
4. CPU 生成参考像素，FPGA 在另一张帧生成结果，缓存同步后逐像素对照；
5. 通过后输出 `GAME_PIXEL_MATCH`，重置真实游戏并准备第一帧；
6. 输出 `APP_MODE mode=GAME` 与 `DISPLAY_READY`，进入运行循环。

这个启动自检不等于每帧读回整屏。正常游戏不会为“检测”每帧将最终帧搬回电脑。引擎写回 DDR 是为了正常显示，本来就需要，与自检无关。

### 2.3 一次主循环

```text
非阻塞发送积压日志、读取有限数量串口字节
        ↓
取当前帧的不可变 UI 快照，更新后台 HUD
        ↓
启动当前命令 bank 的第一个区域
        ↓
循环：轮询硬件区域完成 → 启动下一区域
      同时分批推进下一帧的游戏逻辑/描述符准备
        ↓
当前画面全部绘制完成，若下一帧准备未结束则补完
        ↓
记录本帧工作时间，提交后台帧、等待接受
        ↓
交换完整帧缓冲、命令 bank 和帧快照
```

CPU 将敌弹更新分成每次最多 32 个槽、绘制列表生成分成每次最多 32 项，给硬件轮询留出机会；玩家、武器、敌机、拾取等每逻辑步先由 `sh_step_begin()` 完成，敌弹随后通过 `sh_step_bullets()` 分段更新。不能把一次“分段调用”当作完整逻辑帧多次执行。

渲染帧 N 与 CPU 正在推进的下一帧状态分离，避免混用。工作耗时统计在换帧等待前结束，包含本轮 HUD、提交、绘制和未隐藏的 CPU 准备；它不等于各统计项简单相加，因为其中有重叠。

### 2.4 逻辑 60Hz 与补步

使用真实微秒累计，而不是“每画一次就假定过去 1/60 秒”：

```text
phase += elapsed_us × 60
ticks_to_run = floor(phase / 1000000)
phase %= 1000000
```

最多补 4 个逻辑 tick；超出的数量累计到 `dropped_ticks`，不会静默丢掉。初始相位设为 500000，即半个逻辑周期，减少采样恰好落在边界时反复 0/2 步的抖动；平均逻辑速率仍由真实时间决定。

主循环在工作开始处采时间，再执行 HUD，避免 HUD 开销改变逻辑采样位置。玩家移动、发射周期、关卡计时以逻辑 tick 为单位，FPS 以实际显示新帧计数计算；两者都要观察，不能用“画面 60Hz”掩盖逻辑减速。

### 2.5 从游戏对象到引擎命令

游戏逻辑坐标为 480×560；HDMI 左侧主画面为 448×480，右侧 192×480 为面板。将逻辑中心映射到屏幕后减去纹理半宽/半高，得到目标左上角：

```text
screen_center_x = trunc(logical_center_x × 448 / 480)
screen_center_y = trunc(logical_center_y × 480 / 560)
draw_x = screen_center_x − texture_width/2
draw_y = screen_center_y − texture_height/2
```

这属于 CPU 坐标转换；纹理像素尺寸已离线准备，不是引擎逐像素运行任意缩放。随后应用材质透明边界、画面裁剪、区域相交，生成 16 个区域各自的描述符列表。

图层大体按如下顺序建立：Boss 血条环 → 自机弹与拖尾 → 敌弹 → 敌机/Boss → 玩家 → 道具 → 效果 → 判定点/辅助选项/背景粒子 → 激光表现。相同位置上后提交的内容覆盖或混合在前面的结果上。改变该顺序会改变透明视觉，不能仅为了分组提交而任意重排。

一个逻辑对象可能产生多个图案，例如自机弹主体加两段拖尾；一个图案跨区域又可能产生多个描述符。因此 `objects`、`bullets`、`descriptors` 都不相同。

## 3. 游戏的计算规则与关卡状态机

本节解释当前平台实现的实际计算。原作相同之处与移植近似不能混淆；具体的离散数值、随机序列和视觉不等价于完整 PC 原作。

### 3.1 对象池和内存结构

游戏状态枚举为 TITLE=0、PLAY=1、PAUSED=2、OVER=3、CLEAR=4；当前应用初始化直接进入 PLAY，入口菜单由独立 Menu 程序负责。暂停时不执行正常运动/发射，恢复后继续既有状态；R 重开建立新关卡状态，仅显式保留当前会话 HI。

| 对象池 | 容量 | 说明 |
|---|---:|---|
| 敌机 | 64 | 0 槽保留给道中/最终 Boss，1～63 普通敌机 |
| 自机弹 | 96 | 武器种类共用，含年龄、速度、伤害等 |
| 敌弹 | 1280 | 紧凑属性与 Q16 运动分开存储 |
| 效果 | 64 | 短寿命粒子 |
| 道具 | 128 | P 和点共用 |
| 延迟齐射队列 | 12 | 定时触发成对子弹 |

每个敌弹属性 `sh_bullet` 为 8 字节，运动 `sh_rain_motion` 为 6 个 `int32_t`、24 字节，共 32 字节/敌弹；1280 个约 40960 字节。Q16 坐标只保留一份，不再维护重复 Q8 坐标。`sh_bx/by()` 将 Q16 除以 256 得 Q8，需要整数像素时再除 `SH_Q=256`。

`sh_bullet.hp` 被用作已擦弹标志，不是敌机血量；`cooldown/kind/pad` 在弹型状态机中有各自含义。不要把它当成通用敌人结构体扩展。游戏内存紧张，盲目增加池容量会使链接超出 CPU RAM，而不是自动转移到 DDR。

密集发射时使用空槽位图，以 32 槽一组记录空位，取最低空位，保持确定的最低空槽分配次序，避免每发一弹都从头反复线性搜索整个池。位图和生成时机要与槽回收配合；池用尽时增加 `dropped_spawns`，不能丢弹后仍把场景描述成完全相同。

### 3.2 定点、角度、随机与运动

- 玩家/普通 actor 使用 Q8：实际值=`stored/256`。
- 敌弹运动使用 Q16：实际值=`stored/65536`。
- Q16 乘法用 64 位中间值，再除以 65536；有符号除法的向零截断不能随意替换为对负数行为不同的移位。
- 一个整圆为 65536 角度单位，16384 为四分之一圆。
- 三角查表：`i=(angle&65535)>>8`、`k=angle&255`，在 256 项正弦表相邻项之间线性插值；余弦等于正弦加 16384。
- `cb_angle()` 通过反正切表、象限和分量比例得到近似角度，无运行时浮点 atan2。
- 随机为 `rng=(1664525×rng+1013904223) mod 2^32`。固定种子使本平台可重现，但不代表与原作使用同一随机序列。

多数敌弹先执行 `position+=velocity`，再执行速度变化。趋向目标速度的一般计算是：

```text
v_next = trunc(v × retention / 65536)
       + trunc(target_v × (65536-retention) / 65536)
```

另有 `(4v+target_v)/5`、恒加速度、延迟启动、减速后转向等弹型专用规则。两项分别取整与先求和再取整可能有一单位差别，移植时按对应源函数保留顺序。

雪花运动使用预计算的速度衰减和累计位移表，代替反复从生成时刻重演。理想连续表达为 `v_t=v_0×r^t`、`Δx=v_0×(1-r^t)/(1-r)`；实际表在定点计算规则下生成并使用有限范围索引，分裂时仍保留原定时刻、方向和数量。查表是以存储换运算，不是减少应当存在的弹幕。

晶雨的两种主要运动也可直接从公式理解：细雨初速度向下 1，最高难度加速度为朝玩家的 Q16 单位向量除以 100；瞄准成对弹的目标速度为该单位方向的 2 倍、初速度为目标的 3.3 倍，此后每 tick 用 `(4v+target)/5` 收敛。发射时计算单位向量一次，不为每枚弹每 tick 重做瞄准平方根。当前最高难度每 10 tick 从顶部随机位置发 5 枚细雨；500 tick 循环中，满足窗口/间隔条件时发出 12/13 枚交替的瞄准扇形。实现判断是 `cycle>=110 && cycle<510` 且间隔 20，而 `cycle=t%500`，所以实际还受 cycle 最大 499 限制；修改循环长度时必须连同窗口边界一起检查。

### 3.3 玩家与武器

初始化 3 条生命、Power=100（显示 1.00），最高 600。每个 P 增加 5；武器档 `rank=min(power/100,4)`，显示的 5.00/6.00 不再增加 rank。

普通速度 Q8=1440，即每 tick 5.625 个逻辑像素；按住 Shift 时为 720，即 2.8125，正好一半。对角线使用 `181/256` 近似 `1/√2`，避免斜向明显更快。玩家图像锚点限制在 x=0～448、y=0～528；判定中心为锚点加 `(16,16)`。

| 武器 | 基础伤害 | 发射节奏 | 运动/升级逻辑 |
|---|---:|---|---|
| 正面主弹 | 50 | 每 3 tick，左右交替 | 逻辑中心 x±10，向上 20 像素/tick |
| 成对散射 | 35 | 每 16 tick 建立齐射 | p=0～rank，延迟 `5p`；角度 `-16384±(1024+358p)`，速度 18 |
| 非慢速追踪弹 | 175 | 每 21 tick，受模式切换延迟约束 | 每 option 一发，初速 8，前 60 tick 调向 |
| 慢速针弹 | 64 | 每 3 tick，受模式切换延迟约束 | 每 option 一发，向上 20 |

聚焦模式变化后延迟 8 tick，避免在切换同一瞬间不受约束地发射两个分支。option 的位置由同一函数供绘制和发射使用：非慢速时按 rank 在背后/左右分布；慢速时绕玩家旋转，半径 52，四档外侧两枚半径 78，方向和转速按源码设置。

追踪实现：每逻辑步先建立有效敌人索引，再为追踪弹找最近存活目标；超过 60 tick 不再追踪。令 `t=age`、`u=t³/60³`，转向权重为 `4u(1-u)`；速度 Q8 为 `1024+(t+1)²×1024/3600`。朝目标施加加速度，再以整数平方根归一化速度。它仍在 RISC-V 执行，FPGA 只负责画结果。

### 3.4 碰撞、死亡和擦弹

玩家可见图案不是整张都受击。判定点显示在中心，敌弹撞击使用玩家中心半径 3 的圆与敌弹收缩矩形相交。对矩形求离中心最近点 `(nx,ny)`，若 `(cx-nx)²+(cy-ny)²<=9` 则相交。24 规格敌弹内缩 5，其他常用规格内缩 3；这是本版实际近似判定，不从透明像素逐点检测。

普通敌机体撞击使用中心距离半径 7 的检查；Boss 体撞击另用相应矩形和状态限制。自机弹命中普通敌机的近似半径 30，Boss 42；先排除轴向距离，再比较平方距离。普通敌机优先、Boss 最后，一发自机弹命中一个对象后消耗；同 tick 被击破目标会从有效判断中排除。召唤阶段普通敌人不可受击，Boss 转场期间不受击。

死亡处理：若不处于无敌/受击保护且正在游玩，生命减 1，保护 210 tick，重生动画 60 tick，连击归零，保留 `floor(0.7×Power)`，掉落 `max(2,floor(0.03×原Power))` 个 P，清除敌弹和激光围栏，最终生命为零进入 GAME OVER。重生位置用既定多项式平滑进入画面，不能在保护结束前误用越界初始化坐标做正常玩家运动。

擦弹：玩家中心距敌弹中心小于 20 逻辑像素，且该弹尚未擦过，则 `graze+=1`、得分加 10，设置该弹擦弹标志。每弹只加一次；无敌模式仍可计擦弹，因此测试成绩不可当作正常通关成绩。

### 3.5 道具与分数

普通掉落初速带少量随机横向量，向上初速 1；横速每 tick 乘 `15/16`，纵速每 tick 增加 `1/32` 至下落速度 1。玩家中心到达 y<160 或进入吸引范围后自动追向玩家，速度取当前位置差的 `1/8`。

吸引距离使用曼哈顿距离 `|dx|+|dy|`：普通 30、慢速 60，拾取阈值 18。P 增加 5 Power，最高 600，并加 25 分。点道具数量加一，当前点价值按平台公式：

```text
point_value = 10000 + graze×5 + (448 − player_anchor_y_integer)×4
```

其中 448 是当前源码的常数；该项是平台简化规则，不应擅自写成“完整复现原作计分”。总分饱和至 999999999，最高分跟随更新。

普通敌机被击破加 100 分、连击加一，按该敌人配置掉 P/点，并产生短寿命效果；敌机血量使用 32 位值。每个敌类的血量和关卡事件表共同确定消灭难度，不以贴图大小自动推算。

实际血量映射为：`ST_SINE/ST_DROP=100`；`ST_CIRCLETOSS/ST_INSTANT/ST_WAVE=2000`；`ST_EXPLOSION=8000`；`ST_TRI=28000`；其余普通敌类为 400。伤害达到剩余 HP 时击破，较小时仅减血；仍处于 summon 的敌机直接忽略伤害。

### 3.6 道中状态机

状态路径为：开场 → 道中 Boss 入场 → Icy/Snowflake 阶段 → Perfect Freeze 阶段 → 离场 → filler/等待后半 → 后半敌群 → 最终 Boss。

| route | 含义 | 时间/切换 |
|---:|---|---|
| 0 | 开场敌群 | 第 0～2699 tick，45 秒 |
| 1 | 道中 Boss 入场 | 120 tick |
| 2 | 道中第一阶段 | HP=24000，限时 1200 tick |
| 3 | 道中第二阶段 | HP=24000，限时 3000 tick |
| 4 | 道中 Boss 离场 | 120 tick |
| 5 | filler/等待 | `post_start=max(mid_end,4880)` |
| 6 | 后半敌群 | 从 post_start 起 2560 tick |
| 7 | 最终 Boss | 独立六阶段状态机 |

事件表共 525 条，每条 28 字节，分为开场、filler、后半三段。事件数量不等于同时存在敌机数；提前击破道中 Boss 会改变 filler/后半衔接，应按事件所属段和截止条件取消过时事件，不能把所有段一次性补发。

事件记录 `sh_stage_event` 的布局依次为：`uint16_t tick,group`；`uint8_t kind,flags,power,points`；`int16_t x,y,tx,ty,vx,vy,ax,ay`；`uint16_t exit_time,section`。三段计数为 125/308/92，起始记录号为 0/125/433。生成事件时 x/y/目标坐标按记录值乘 16 转为 Q8，速度/加速度字段按各行为直接解释；flags 可选择红色材质、随机位置及曲线位置。不要把这些 int16 坐标直接当作整数像素。每段使用独立游标，只在记录 tick 等于当前 tick 且满足该段条件时生成，过期记录推进游标而不补发。

普通敌人行为由类型状态机驱动，主要规则如下。精确生成位置、掉落与时间在 `stage_events.h`/素材事件包中，精确运动系数以 `stage1.c` 为准。

| 类型 | 行为 |
|---|---|
| `ST_BURST` | 接近、瞄准扇形、退出 |
| `ST_CIRCLETOSS` | 侧向经过，圆环和瞄准粗米弹 |
| `ST_SINE` | 曲线移动并间隔发射瞄准球 |
| `ST_CIRCLE` | 曲线/绕行轨迹，周期发射米弹 |
| `ST_DROP` | 穿过画面并发射下落/瞄准弹 |
| `ST_MULTI` | 靠近后重复扇形齐射再离场 |
| `ST_INSTANT` | 停留释放两圈弹幕后退出 |
| `ST_WAVE` | 召唤、瞄准射击和三角波形弹幕 |
| `ST_EXPLOSION` | 延迟后 60 方向×5 速度，形成 300 发爆散 |
| `ST_TRI` | 长时间旋转齐射及附加环，持续时间较长 |

道中第一阶段以六臂雪花、分裂和速度衰减为主；第二阶段以持续生成、分批冻结、等待、移动、瞄准米弹、逐步解冻为主。冻结/解冻通过 generation、遍历游标和等待状态推进，避免在同 tick 对全池做重复复杂工作；既定状态阶段间的时机仍按逻辑 tick 计算。

### 3.7 琪露诺最终 Boss 六阶段

| 阶段 | 显示名称 | HP | 限时 |
|---:|---|---:|---:|
| 0 | ICEPLOSION 0 | 26000 | 20 秒 |
| 1 | CRYSTAL RAIN | 33000 | 40 秒 |
| 2 | ICEPLOSION 1 | 30000 | 20 秒 |
| 3 | SNOW HALATION | 40000 | 50 秒 |
| 4 | ICICLE CASCADE | 40000 | 40 秒 |
| 5 | CRYSTAL BLIZZARD | 40000 | 60 秒 |

每阶段开始清敌弹、自机弹和效果，设置血量/限时/目标点，转场等待 90 tick。转场不推进攻击逻辑；攻击到期或血量清零进入下一阶段，最后进入 CLEAR。

Boss 伤害保护：阶段前 60 tick 不接受伤害；60～300 tick 逐步解除，令 `factor=min(240,t-60)`。使用余数保留：

```text
scaled = damage × factor + remainder
actual = floor(scaled / 240)
remainder = scaled % 240
```

这样小伤害不会因每次整数截断而永久损失。实际伤害不超剩余 HP。累计实际伤害达到 2500 时掉 P；击破加阶段奖励 `50000+剩余tick`，另加 1000；超时加 5000。符卡阶段按代码掉落 P/点，收取还要求无 miss 且没有启用测试标记。开启过无敌/跳段会标记测试使用，不应算正常符卡收取。

六阶段发射机制：

- **ICEPLOSION 0**：300 tick 循环，瞄准环、顶部向下变速弹与后半随机旋转环；Boss 周期游走。
- **CRYSTAL RAIN**：使用 `taisei_rain.c` 的晶雨发射/定时运动，按本版最高难度参数。
- **ICEPLOSION 1**：330 tick 循环，八方向多束扇形、两侧螺旋布置且延迟启动的弹列、后半加速圆环。
- **SNOW HALATION**：375 tick 循环，在玩家附近记录 14 个围栏顶点，分阶段重连，预警后进入有效激光，再由顶点发散子弹。
- **ICICLE CASCADE**：每 8 tick 成组发射左右各四种速度弹，先减速，再转向/加速到目标速度。
- **CRYSTAL BLIZZARD**：700 tick 循环，上方持续加速度雪弹，随后追逐玩家位置并发射瞄准弹与旋转加速度弹。

### 3.8 半透明预警和激光判定

Snow Halation 在循环 `c=60` 时以当时玩家为中心、半径 200 放置 14 个节点；c∈[60,300) 保留围栏。每 60 tick 改变连接相位，前 30 tick 是预警、后 30 tick 为有效激光。预警 Alpha=72，生效 Alpha=224，所以会看到半透明内容预示下一阶段危险区域。

图形用沿线摆放的晶体/细段贴图表现，碰撞使用连续线段，二者不是逐像素完全等同的判定。对于玩家中心 P、线段端点 A/B，记 `D=B-A`、`V=P-A`、`L2=D·D`、`dot=V·D`，半径 9：

```text
dot <= 0 或 L2=0：检查 |P-A|² <= 81
dot >= L2：       检查 |P-B|² <= 81
其他：            检查 cross(V,D)² <= 81×L2
```

使用 64 位中间值，不必对点到线距离开平方。只对 hot 线段产生伤害，预警不伤害；画面半透明本身不是伤害开关，逻辑和渲染都根据同一围栏时钟派生状态。

### 3.9 新版 Alpha、血条和 HUD

| 内容 | Alpha |
|---|---:|
| 自机弹主体 | 128 |
| 自机弹两层拖尾 | 80、32 |
| P、点道具 | 128 |
| 常规敌弹绘制 | 208 |
| option 图案 | 144 |
| 雪/背景粒子 | 64 |
| 激光预警 / 生效 | 72 / 224 |
| 玩家正常 / 保护闪烁弱帧 | 255 / 96 |
| 中央判定标记 | 255 |

Boss 周围血条以多段图案构成环，已用段/未用段透明度不同。它是渲染器生成的描述符，不是引擎内置的“血条指令”。右侧面板显示分数、HI、Power、点、Graze、生命等；数值通常每 6 个逻辑 tick 更新一次，生命/状态/无敌变化及时更新。两张帧缓冲各有脏标记，避免只改一张导致隔帧闪回。

环形血条分 64 段，点位置按三角表生成横半径 29、纵半径 34 的逻辑椭圆，亮段数为 `floor(boss_hp×64/boss_max_hp)`；亮段 Alpha=255，其余 48。同一枚自机弹先画两段较淡拖尾、最后画主体，拖尾位置由 `position-tail_index×velocity` 得到，未额外增加独立运动对象池。

HI 存于当前游戏会话的 RAM。R 重开保留；退出到菜单再进入游戏、重新加载应用或断电会重置。

## 4. 素材管线、背景和 UI

### 4.1 原图怎样变成可绘制素材

```text
带来源记录的原始图片
    → 离线选帧、裁剪/缩放、必要的材质着色
    → RGB565 转换，透明区写颜色键
    → 打包图集并生成偏移/宽高
    → 生成背景、HUD、关卡事件和包头/CRC
    → game_assets.bin / background_store.bin
    → Flash 或调试器装入 DDR
    → sl_load 装入片上图集 / 背景保持 DDR
```

引擎不认识文件名或 PNG 格式。`game_assets.h` 的每个 `offset` 都是图集内的**像素偏移**；纹理宽高以像素计。纹理表最后一项末端不能超过有效图集长度。

当前游戏图集有效 8064 像素，距 8192 上限仅剩 128 像素，即 256 字节。不要把“8192 像素”误当成“8192 字节”或“8192 张图片”。添加动画帧通常需要删减其他纹理、重新安排图集或修改硬件存储设计。

当前图集含玩家双帧、琪露诺、不同等级妖精、旋涡、主弹、针弹、灵符、追踪球、晶体/米弹/粗米弹、P/点、血条小段、雪/option/判定点等。Boss 与部分敌机使用静态帧，不是完整原作动画播放器。

### 4.2 包头和完整性

游戏包从 `0x47FFC0` 开始，包括 64 字节头及有效负载；当前总长 1460652 字节，有效负载 `GA_BYTES=1460588`，负载 CRC32=`0xB41BD266`。Flash 外层容器还对整个包记录独立 CRC，两个 CRC 覆盖范围不同，不能混用。

参考 [game_assets.json](../03_Assets/game_assets.json)、[game_assets.h](../08_Game/src/game_assets.h) 和 [game_assets.bin](../03_Assets/game_assets.bin)。更换素材后需同步：包内偏移、尺寸、总长度、CRC、C 头文件及 Flash 封装记录。仅覆盖一张原 PNG，不会自动改变已经打包的 BIN。

本交付包包含运行所需的已转换资源和来源元数据。`tools/build_suite.py` 使用这些已打包资源生成固件；修改素材时应按上述像素和包头格式更新资源，再运行像素与完整性测试。

### 4.3 游戏背景如何滚动

使用离线准备的背景图，DDR 中连续存两份 640×480，形成 640×960，方便从任意行起点取连续 480 行：

```text
scroll = floor(game_ticks / 4) % 480
background_row = scroll + screen_y       // 最大 959
background_address = GA_BG + background_row×1280 + screen_x×2
```

重复存储避免底部每行额外处理回卷，屏幕显示其中连续 480 行。当前使用二维背景图滚动，可通过 B 关闭；关闭时主画面为黑，逻辑更新速率保持不变。

Demo 原尺寸背景为 640×432。原尺寸/缓存暗背景是不同数据路径，必须在日志中注明所选模式，不能用低分辨率小背景的指标代替原尺寸背景。

### 4.4 HUD 为什么使用单独暂存

文字、数字和装饰面板由 CPU 在有限的 HUD 内存生成或更新，再通过通用图像搬运合入后台帧；无需每帧 CPU 重绘整张 640×480。游戏的静态面板素材与动态数字分离，双帧各维护更新状态。

更新频率降低的是面板数值重绘，不是主画面或游戏逻辑频率。若修改字体，要核对字模宽高、行跨度、裁剪、目标面板位置和脏行范围；只改字模大小而不改这些值会出现只显示半个字或覆盖相邻行。

## 5. 画面分区与内存布局

逻辑坐标 480×560，映射到 HDMI 左侧 448×480；右侧 192×480 是面板。主画面分为 16 个高 30 行的区域，逐个调用同一合成器，保持原有图层次序。每个区域最多 512 个描述符；拖尾、血条、激光和跨区裁剪会增加描述符量。

| 用途 | 地址/布局 |
|---|---|
| 图集源数据 | `0x005B0000` |
| 原始游戏/素材包头 | `0x0047FFC0`，头长 64 字节 |
| 主背景像素 | `0x00480000`，640×960 组织 |
| 命令 bank 0 | `0x00700000` |
| 命令 bank 1 | `0x00720000` |
| 每 bank 大小 | `0x20000`，16×8192 字节 |
| 辅助材质/背景 | 右侧面板 `0x005B4000`；关卡事件 `0x005E1000` |

完整帧缓冲为 `0x800000/0x900000`，每帧 614400 字节、跨度 1280 字节；HUD 暂存在 `0xA00000`。图集有效 8064 像素，硬件容量 8192 像素。CPU 应用可用区 124KiB，当前占 `125584/126976` 字节，包含 4KiB 栈预算。调整对象池或静态表要重新检查链接内存。

应用使用 `0x700000/0x720000` 双命令 bank：FPGA 绘制当前 bank 时，CPU 推进下一帧状态并写另一 bank。图形硬件使用 DDR DMA 白名单 `[0x400000,0xC00000)`；启动器的高地址暂存另由 CPU 访问。详细协议见 [引擎开发说明](../01_Engine/README.md)。

## 6. 串口键盘协议

### 6.1 按住与组合键

普通串口字母没有“按下/松开”语义。工具发送 `@HH`，HH 为两位十六进制，表示完整按键状态：

| 位/值 | 意义 |
|---|---|
| bit0 / `0x01` | 上 |
| bit1 / `0x02` | 下 |
| bit2 / `0x04` | 左 |
| bit3 / `0x08` | 右 |
| bit4 / `0x10` | 射击 |
| bit5 / `0x20` | 慢速 |

例如 `@11` 为上+射击，`@30` 为射击+慢速，`@00` 为全部松开。板卡在 250ms 内没收到刷新会释放状态，防止工具关闭后角色一直移动。

工具大约每 20ms 轮询键盘，持续按住时每 60ms 重发；松键或失焦发送释放。日志界面低频刷新，并把串口连接和读取放在异步流程，避免 UI 被阻塞。普通终端发 WASD/J 仅形成约 180ms 短脉冲，不能由敲一个 Shift 字符模拟真正按住 Shift。

### 6.2 电脑与板卡职责

串口工具只收发输入/控制和日志，不执行关卡物理、图形合成或 FPS 计算。已写入 Flash 后正常演示不要求电脑安装 Python、GCC、Efinity 或 IDE，只需可用的驱动和串口工具。

同一个串口不能同时被多个程序占用。测试脚本、IDE 串口终端和该工具应有序交接；关闭占用方后再连接，不用反复打开多个窗口抢端口。

## 7. 构建与 Flash 部署

官方 RISC-V IDE 导入 [08_Game](../08_Game)，工程名 `FrameSpeed_Release_Game`，执行 Build Project。使用该目录的 Makefile、`suite.ld`、头文件和 BSP。不要与 `07_Demo` 中同名 C/头文件混编。编译架构为 `rv32im_zicsr_zifencei`、ABI `ilp32`、优化 `-O2`。

输出 `build/framespeed.elf/.bin/.hex/.map`。ELF 包含调试符号和素材加载段；CPU BIN/Intel HEX 导出时排除了素材段。发布时由统一封装工具将 FPGA 配置、CPU 程序和素材合入完整 Flash 镜像。

```powershell
python tools/test_game.py
```

可在逻辑步、碰撞、阶段切换和描述符提交处设断点，但单步/断点期间不测性能。显示模块会继续扫描旧帧；这不代表游戏在继续生成新画面。

### 8.1 密集段实板记录

### 8.2 正确性与运行检查

新版 Game RV32 逻辑/像素测试通过 6964138 项检查，覆盖规则、关卡推进、武器/伤害/拾取、命令裁剪和透明混合等。启动素材 CRC 与 CPU/FPGA 像素对照通过，真实菜单→游戏→菜单切换通过。原始记录见 [06_Verification](../06_Verification)。

### 8.4 常见问题

- Shift 没持续减速：确认串口工具窗口获得焦点，按住状态通过 `@HH` 持续刷新。
- Alpha=0 仍受伤：Alpha 只控制显示，碰撞由逻辑状态决定。
- M 返回失败：独立应用调试尚未建立 Suite 跳板/暂存，先按完整启动流程进入。
- 对象容量未满却命令溢出：检查每个区域的 512 描述符上限和额外效果。
- 贴图修改后无变化：重新生成资源包、头字段/CRC，重新装图集和应用素材。
- 串口无法连接：关闭其他占用者，选择实际端口，查看工具日志。
